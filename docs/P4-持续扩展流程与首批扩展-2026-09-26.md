# P4：持续扩展流程与首批扩展

日期：2026-09-26。P4按原方案是一个**持续阶段**：随着新资料取得，逐栋、逐街区扩展，进度用“已核实的建筑、立面面积和道路长度”来计。本轮完成了P4需要的全部工程能力，也用这套流程实际扩展了一批建筑。**全城远未完成**：精细建筑只占全城OSM建筑记录的0.066%，精细道路只占0.22%。

P3收尾记录见[P3集成验收与完成记录](P3-集成验收与完成记录-2026-09-26.md)。

## 1. 可重复的工作流程

```
公开数据更新 ──► 来源冲突审核 ──► 候选登记 ──► 证据记录 ──► 立面研究 ──► 暂存检查 ──► 纳入默认 ──► 覆盖统计
snapshot-diff      conflicts/deferred  register      facade-studies   kit build   inspect        gate+tiles     coverage
```

| 步骤 | 命令 / 文件 | 产出与门槛 |
| --- | --- | --- |
| 1 取得带日期的快照 | OSM map API `map.json?bbox=…`。沙箱内由浏览器下载，普通环境可直接请求 | `data/evidence/snapshots/<日期>/*.json` + `sources.json`（URL、时间、SHA-256） |
| 2 比对与影响 | `tools/snapshot-diff.py <快照目录>` | 列出已接入建筑中要复核落位的对象、道路块中要重建的源way、待核标线/端点是否有新标签；不自动合并 |
| 3 候选登记 | `tools/candidate-register.py` | 研究区每个外轮廓分为：已接入 / 照片+地址 / 仅身份 / 仅轮廓；另列出地址照片中无法对应OSM地址的条目 |
| 4 证据记录 | `data/evidence/facade-studies.json` | 身份依据（≥2项）、照片（Commons作者、日期、许可、哈希）、逐面观察、模型参数、冲突、未知项 |
| 5 构建 | `tools/build-facade-studies.py` | 自动选定照片立面所在源边；离题名街道超过25m即判为立面无法绑定；替换ID中至少一条必须真正参与渲染 |
| 6 暂存检查 | `tools/build-detail-trial.py` → `?detailTrial=inspect` → `tools/acceptance/run-studies.pw.js` → `tools/acceptance/photo-compare.py` | 加载、404回退、远离释放；照片与模型结构对照图（树木暂隐时画面有标注） |
| 7 纳入默认 | 在证据记录中写 `gate` → `tools/build-detail-tiles.py` → `tools/verify-detail-placement.mjs` → `npm test` | 控制点零残差、每条替换ID只属于一个块、没有误分组填充、不与邻楼交叠 |
| 8 复验与统计 | `run-default-stress.pw.js`、`run-regression.pw.js`、`tools/coverage-stats.py` | 验收记录JSON，覆盖率只计已接入对象 |

道路同样有配套工具：`tools/road-coverage.py`（实测长度、路口、断面与连接检查），`data/detail/upgrades.json`（数据升级链）。

## 2. 来源冲突的处理规则（本轮实例）

- **名称冲突不改模型**：沙面大街59号，OSM旧名是“德国领事馆”，荔湾区规划附表七写的是“亚细亚火油公司旧址”。两者都登记，模型不依赖其中任一说法。
- **楼层冲突按立面照片建模，并同时替换部件**：64号的OSM部件标签是3层，照片正面只能看到2层加女儿墙。记录可能存在后退的第三层，替换父轮廓和部件两条记录，避免残留重复体量。
- **立面无法绑定就不建模**：59号外轮廓北边离题名街道55m，照片中立面前方紧贴围栏，可以对应不止一条边。结论是暂缓，不做猜测。
- **多门牌照片需要位置证据**：“2、4、6号”“19–29号”这类照片覆盖多栋建筑，不能只按其中一个门牌套到某个外轮廓上。
- **新版本不等于已核实**：`snapshot-diff` 只报告变化，不自动采用。

## 3. 本轮扩展结果

- 第二批2栋纳入默认主城：C06渣打银行旧址（抹角入口加北、东两面，共3面）和C17旗昌洋行旧址（10开间三层拱窗）。纳入前完成暂存检查、4轮404回退和照片结构对照。[对照图](research/p3-building-expansion/photo-compare-batch2.jpg) · [验收](research/p4-extension/batch2-validation.json)
- 工具包补充了多面研究、拱形顶饰和屋顶亭；多面样件统一合批。
- 2026-09-26的沙面和花城快照比对：研究区168个基线建筑没有改动；13栋已接入建筑无需复核；花城样区2,587个要素与P0完全一致，道路块和14条待核标线都没有新资料。新快照中另有26个建筑在P0裁切范围外，并且在基础快照之前就已存在，不是新增编辑。[比对报告](research/p4-update/diff-2026-09-26.json)
- 63个Overture补充轮廓的第二轮几何复核：57个在OSM中无对应，6个在刷新范围外，全部保持hold。没有影像或身份资料，不能替换或删除任何对象。

## 5. 道路扩展的评估

沙面大街在OSM中是两条行人道路，约846m，与规划公示稿“长约846米”一致。公示稿同时写“宽约12.9米”，但两条行车道中心线实测相距约20–26m，因此12.9m到底指单侧、单条行车道还是另有口径，目前无法确定。所以**不据此生成沙面道路精细块**，登记为待澄清的宽度口径。花城样区之外，其他道路还没有达到P3那种“有中心线+车道标签+测绘人行道”的资料密度。

## 6. 性能随扩展的变化

每个立面研究约9–13个网格，一个块8栋约90个网格。在街景视角，全部13栋精细建筑比基础体量多约68次绘制调用，帧时中位数仍受120Hz垂直同步限制。如果一个街区扩展到上百栋，需要改为按块合批（用顶点色合并同类材质），届时要在当时的建筑密度下重新实测，不能从本次数据外推。

## 7. 持续事项（P4开放清单）

1. 6栋“照片+地址”候选：按第1节流程逐栋处理。每栋至少取得一张能绑定立面的照片。
2. 多门牌照片和50个未对应地址的照片：需要位置或平面匹配证据。
3. 已接入建筑的侧面、背面：需要新照片，否则保持简化。
4. 实测尺寸：需要可复用的测绘或立面资料；拿到后通过 `upgrades.json` 升级链替换估计值。
5. 按月或按需重复第1–2步，比对新快照。
6. 手机和集成显卡上的性能与内存测试：需要真实设备。

这些都是按资料持续推进的事项，不是本轮漏做的工程。所有工具和门槛已经就绪。
