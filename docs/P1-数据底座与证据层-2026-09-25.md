## 3. 运行端使用

基础数据加载后即可取得 `D.buildingSourceIds` 和 `D.roads[i].sourceId`。资料查询需显式加载：

```js
const index = await D.loadEvidence();
// 等价按需入口：await D.evidenceReady
if (index) {
  const building = index.getEntity('osm:w352610322');
  const network = index.getNetwork('osmHuacheng');
  console.log(building.facades, network.restrictions);
}
```

现有控制台入口可以使用 `window.__gz.D`。状态由 `D.evidenceStatus` 提供：idle/loading/ready/error/unavailable；加载失败时 `D.evidenceError`记录原因。当前实现缓存本次加载结果，失败后需重新加载页面重试。

查询接口包括：

- `getEntity(id)`：源标签、字段来源、关系与逐立面资料。
- `getNetwork(id)`：节点身份、way节点序列、原始道路标签和限制关系。
- `getCandidate(id)`：读取候选与审核状态。
- `getReplacement(id)`：仅当有明确审核证据且后续模型资产通过验证时才返回资产；当前全部返回null。

字段中的 `sourceId`指向数据源注册表，实体 `id`指向真实源要素；两者不能混用。OSM height、楼层、颜色等标为reported，不自动标为verified。缺失高度仍为unknown，而不是把当前渲染推算高度反写成事实。

`resolveField`优先保留有证据的字段，同级不同值返回conflict；无来源和审阅证据的verified值被忽略。这是后续精细模型的取值入口，当前程序化渲染器尚未切换到逐面参数。

## 4. 道路与部件边界

拓扑按node ID建立关联；坐标相同但ID不同的点不会自动合并。保留地下通道、footway、steps、单行方向、access、条件限制和分层标签。`transportClass`只是分类，不能据此判断所有交通方式的合法通行。

限制关系保留from/via/to，支持via-node和via-way。缺少成员的关系保留并标记incomplete，不静默丢弃。**本阶段没有实现路径规划或让现有车流执行这些限制。** `routingImplemented`明确为false。

全城旧快照没有节点ID的道路不会被伪造为完整拓扑；目前完整网络覆盖只声明manifest中的花城大道样区。采集器已更新为保留身份/节点/成员，并扩大道路查询范围。本轮没有重新下载全城Overpass数据；新归一化逻辑已用完整P0样区及缺失节点场景测试，新全城查询仍需在真正刷新快照时验证服务响应。

建筑父子关系只有明确的building关系成员才标为explicit。当前旧快照没有可用的完整显式关联，实际数据中该状态为0，保留unresolved。已用明确outline/part关系的测试样例验证支持能力。

原有渲染端的空间启发式部件替代逻辑仍在，本阶段没有把它升级为真实关系、也没有改动已有几何。这部分在P2真实模型替换时必须继续核对，不能仅凭当前关系字段认为部件问题已解决。

## 5. 候选与照片规则

63个候选的人工状态全部为pending。P1提供记录、验证和查询入口，没有执行几何替换，也没有自动删填充建筑。未来批准候选需保存审阅人、证据引用，并完成模型/空间冲突检查后再进入渲染链路。

逐面资料使用front、side-a、side-b、rear、roof等人工稳定键，避免轮廓边序变化导致照片绑错面。朝向推定、可见范围、年份差异与未知尺寸沿用P0记录。未知背面不会复制正面资料。

源数据库维持ODbL及底层来源署名；照片按每张独立许可处理，不能统一套代码MIT许可。`manifest.json`和`facades.json`保留相应记录。

## 6. 验证结果

执行前：原有2项构建测试通过。

开发过程先增加失败用例，随后实现并验证：

- 完整保留节点序列、版本、成员角色；中间节点缺失时不连接两端制造假线。
- 不因二维坐标重合而合并节点，地下人行路径仍有身份与层级。
- P0的11条真实限制及4条via-way保持完整；缺失关系成员显式报状态。
- 源实体ID与输入顺序无关，显式建筑部件关系可关联。
- 未知背面、同级冲突、无证据verified字段、重复候选和坏引用均有覆盖。
- 旧版数据兼容，不认识的几何版本拒绝解码。
- 证据包按需加载；404时原有建筑、道路与植被仍可用。
- 使用P1前基线，对59个渲染分段逐一比较SHA256，并比较原点、地形、地标等关键元数据。

最终 `npm test`：**15项通过，0失败，0跳过**。构建快照已更新，仓库产物与当前构建一致。语法检查与 `git diff --check`通过。

浏览器实际验证使用本任务临时的5174服务，后台操作：

这证明数据接入与基本场景兼容，不证明建模已达到1:1，也不是全设备性能验收。临时验收页和临时服务不作为产品入口。
